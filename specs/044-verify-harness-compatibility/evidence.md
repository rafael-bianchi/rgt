This is the pre-implementation baseline. For the current OpenCode native result and its exact supported tuple, see [`docs/compatibility/support-matrix.md`](../../docs/compatibility/support-matrix.md) and the [native verification record](../../docs/compatibility/verification.md#native-opencode-read-acceptance-2026-09-26).

**Observed**: 2026-09-26

**RGT baseline**: local `develop` at `5bfff8597e283532f51f4ddb22c675e70808c1d7` (the feature branch starts here).

**Comparative RTK baseline**: [`rtk-ai/rtk` at `a89a31494670fcec8ffa20d939dd94c64bd998fb`](https://github.com/rtk-ai/rtk/tree/a89a31494670fcec8ffa20d939dd94c64bd998fb). **Evidence rule**: RTK source shows how RTK integrates; it does not by itself prove that RGT works in a client. “Verified” requires a recorded RGT run in the real client, with client version, platform, event, outcome, and graph result. No RGT client integration has that evidence in this baseline.

## Test and Claim Limits

- RGT's [installer tests](../../tests/contract/hook_installer.rs) assert the artifacts RGT currently emits, including the Gemini and Vibe forms above. Its [parser tests](../../tests/unit/hook_parsers.rs) use constructed event payloads. Neither set proves that a client loads the integration.
- [`rgt doctor`](../../src/cli/doctor.rs) currently treats the existence of any known artifact as enough for the aggregate hook check. It does not inspect whether the named client loads an active RGT registration.
- A local CLI search found OpenCode, Pi, and Codex on `PATH`; this is not a complete inventory of GUI applications. No paid agent session or GitHub workflow was run for this baseline.
- RTK's current guide also lists Trae, OpenClaw, Oh My Pi, and Factory Droid. Their presence makes RGT's older “full RTK parity” wording stale; adding them is outside this feature.
